# Founder operating directives recoverable from the repository

This is executable content, not a pointer index. It preserves the current strategy,
adds the founder's operating controls, and records `decision_changed: []`.

## Capability factory and compounding loop

Operate SW as a factory at office scale—on the order of one hundred coworkers and
agents when useful provider capacity allows—not as a small assistant set. Maintain
continuous automations, skills, harnesses, packs and nodes. Every consequential
capability must pass the full loop:

The scale target is one hundred coworkers and agents when the platform can sustain
useful accepted throughput.

`discover/create → real-operation test → validate → extract → package → redeploy → improve → retain, supersede or delete`.

Provider-resident success is incomplete. Proven mechanisms become principal-owned,
portable IP: prompts, skills, code, harnesses, integrations, agent configurations,
operating packs, evaluation assets, schemas and reusable modules. The active
strategic operating loop compounds both delivery and the mechanism that creates the
next operator:

`operate → observe → measure → challenge → research → discover → reproduce → learn → change live mechanism → independently retest → package successor`.

Every material unit returns a task effect and factory learning. A wave completes
only with tested mechanism improvement, evidence-backed deletion/supersession, a
qualified new capability, or a measured topology/model/context/evaluation change.

## Founder interface and activation

The founder interface is voice-first: speech intake → semantic strengthening →
read-back of consequential interpretation → intent/authority confirmation → typed
durable event → delegated execution → consolidated evidence return. Do not make the
founder a routine relay, monitor, comparison engine or merger.

The founder activation and acquisition package must say exactly what to buy, set up,
connect and delegate, with provider/account, plan or SKU, quantity, access scopes,
security owner, verification step, cost/renewal surface and stop condition. It must
cover the ChatGPT project estate, Cursor internal factory, codenamed SW exchange,
Manus accounts/connectors, model/API capacity, storage/backup, code/runtime, domain
and identity controls. Nothing is called acquired merely because it was recommended.

## Successors, knowledge and governance

Every accepted operator must produce launch packages that allow at least ten to
twenty next operators to start materially better: immutable source snapshot,
purpose, authority and forbidden actions; exact runtime/model/tool configuration;
disjoint ownership map; inputs and hashes; step-by-step launch; result transaction;
tests and acceptance criteria; recovery and stop procedure; return route; known
limits; and supersession links. G0/G1/G2 comparisons must show lift without
authority, evidence or durability regression.

The minimum successor objective is ten to twenty next operators launched better
than the incumbent.

Constitute a data and knowledge governance office that owns stable identity,
provenance, source/currentness, ontology, access class, retention/deletion,
redaction, quality, conflict, supersession, lineage, evidence state and portable
knowledge packages. Provider memory is never constitutional authority.
