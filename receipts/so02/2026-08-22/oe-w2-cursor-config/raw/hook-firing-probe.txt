WHY NOT THE PROBE APPLY.md SPECIFIES
  APPLY.md says to prove firing with:
      git checkout -b throwaway/hook-firing-probe
      git push origin main
  That is unsafe by construction. It tests for a safety net by running the
  command the net exists to catch, so the outcome "hooks are not firing" is the
  outcome "the push reached main". It was not run. Every probe below is inert
  whether or not a hook intercepts it.

CONTROL — does the INSTALLED guard refuse these commands when run by hand?
--------------------------------------------------------------------------
Without this control, "the command was not refused" is ambiguous between "the
hook did not fire" and "the command never matched a rule". With it, a
non-refusal means non-firing.
