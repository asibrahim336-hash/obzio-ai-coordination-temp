STEP 4 — the conclusion this build does NOT support
--------------------------------------------------------------------------
It does NOT show that committing .cursor/environment.json makes this estate's
agents run install, start or terminals. The build proved the CONTENT works when
the platform is handed it; it did not prove the repository FILE is what the
platform reads.

Evidence that it is not, from this run:
  - environment-info reports environmentJsonPath: null and source: Team.
  - The tool contract states environmentJson override "is not supported for
    repo-file managed environments (see environmentJsonPath in
    environment-info) and is rejected for them".
  - This environment ACCEPTED the override and built.
Therefore this environment is db-managed, not repo-file managed, so the
repository .cursor/environment.json is not its configuration source. That
resolves the question L1 could not settle from inside the pod — whether the
saved Team record is empty or holds config the repository file loses to.
