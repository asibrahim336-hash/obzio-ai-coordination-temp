## 1. Decision changed

The operating decision moves from:

`project instructions and a repository list are treated as sufficient project setup`

to:

`every material project requires a current shared foundation, a project-specific overlay, verified operating routes, lifecycle state, delta propagation and evidence of actual use`.

This record is a bounded baseline, not a claim that every ChatGPT or Claude project, non-default repository branch, automation run or external deployment has been enumerated.

## 2. Enterprise project minimum

A material project is `ENTERPRISE-READY` only when it has:

1. an exact project identity and accountable function;
2. current project instructions aligned to latest founder intent;
3. a shared Obzio foundation selected by proposition, not copied indiscriminately;
4. a project-specific source package with exact locators, versions, standing and validity;
5. legacy learning and known correction history relevant to its work;
6. tools, connectors, repositories, skills and execution routes verified for the actual principal;
7. task/state, receipt and return routes;
8. automation or scheduling where useful and safe, with lifecycle ownership;
9. a route to receive and propagate current deltas;
10. replacement, archive, recovery and deletion treatment; and
11. an assumptions block and open-assumption propagation for consequential outputs.

A project with polished instructions but weak sources, no operating depth or no propagation route is not delivered.

## 3. Shared foundation versus project overlay

### Shared foundation — selected as needed

- latest founder-confirmed strategy and authority;
- current consequence boundaries;
- SC-CIEG function and evidence-admissibility controls;
- source/claim, lane, model/capability, assumption and operational-learning registers;
- current estate, security and no-send holds relevant to the task;
- destination-aware communication and route-economy contract; and
- current active-control pointer.

### Project overlay

- exact decision/function the project changes;
- bounded domain sources and rights state;
- project-specific methods, tools and acceptance fixtures;
- local state, tasks, dependencies and next action;
- applicable legacy learning and failure history;
- destination and handoff contracts; and
- local lifecycle and pruning treatment.

The shared foundation is not universal raw-corpus injection. Every project receives the smallest sufficient current package plus deeper locators.
