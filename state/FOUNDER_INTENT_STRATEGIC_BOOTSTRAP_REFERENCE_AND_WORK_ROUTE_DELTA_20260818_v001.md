### 2.1 Compact semantic bootstrap is the preferred form when it preserves execution quality

Where the destination can reliably dereference durable current state, Ahmed expects a compact, precise launch command or bootstrap seed that gives the destination enough information to recover the complete package itself.

The command should identify, as applicable:

- exact destination/function;
- semantic/currentness root;
- repository or other durable source location;
- immutable identifier or exact path/version;
- what must be retrieved;
- standing authority and consequence boundaries;
- required outcome;
- return/receipt route; and
- fallback if dereference fails.

The objective is not brevity as aesthetics. It is high-integrity context recovery with minimal founder handling and minimal transcription or semantic drift.

### 2.2 Full-file delivery remains valid when it is genuinely stronger

Ahmed does not prohibit downloading or manually transferring the complete launch file.

If the complete file materially improves destination reliability, preserves instructions that cannot be safely dereferenced, avoids connector/access failure, or is otherwise the strongest and most reliable current route, the operator should say so and use it.

The operator must distinguish:

`compact dereference route | complete-file route | strongest route | most economical adequate route | reliability/context trade-off | reason selected`.

Do not convert a founder preference for strategic referencing into an ideological ban on manual transfer.

### 2.3 Packaging and transport are part of strategy

A correct task can still fail if its delivery packaging is weak.

The system must design commissions for the actual recipient and its operating envelope, including whether it can:

- access GitHub/private repositories;
- follow durable pointers;
- open files or attachments;
- preserve long context accurately;
- distinguish current from superseded state;
- continue after source admission; and
- write durable receipts.

The destination should not be expected to infer where a referenced v008 object lives from a bare name.

### 2.4 Source architecture should maximise strategic dereference, not duplicate bulk

ChatGPT projects and other operating nodes should not be filled with large duplicated source corpora merely because files can be uploaded.

Where robust, use source documents as strategic indexes, manifests, semantic roots, retrieval maps and high-value local overlays that tell the node where authoritative detail lives and how to recover it.

Where local copies materially improve reliability, latency, source admission or offline continuity, include them.

The architecture should optimise source quality, currentness, retrieval reliability, context cost, portability and execution quality rather than maximise file count or minimise it dogmatically.

### 2.5 Founder review is evaluation, not a permission gate

Ahmed may inspect a proposed launch route to understand the strategy, challenge weak packaging and improve the plan. That inspection does not automatically create a new permission gate.

A founder evaluation can change strategy if Ahmed identifies a real defect. It should not be represented as approval theatre where standing authority already exists.
